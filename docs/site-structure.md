# Структура витрины

Дата: 27 сентября 2026. Документ архитектуры URL и страниц. Стек, CMS, домены, вёрстка, макеты, SEO-шаблоны title/H1, фейковые топы и внедрение — вне скоупа. Без «ок» владельца ничего не внедрять.

Опора: [контекст](project-context.md), [обзор практик](practices-overview.md), [образец](design-sample.md). Живой скоринг и методика — в другом Project; сюда только опубликованные срезы.

**Не делать:** пересбор весов Калининграда; скоринг на этом сайте «на глаз»; продажа мест в таблице; расчёт рейтингов на витрине.

Рабочий процесс с владельцем: дальше по 1–3 вопроса за раз.

## 1. Принято владельцем

- **Источник рейтингов — 0а.** Три готовых среза из скоринг-проекта (запросы / отзовики / исследование). Витрина только публикует. Считать (а) и (б) на витрине (бывший 0б) — запрещено.
- **Корень — оглавление.** `/` существует сразу: издатель, что это за витрина, ссылки только на регионы и типы с опубликованным срезом, ссылка на методику. Федерального топа и «топ России» нет.
- **Директ = тот же URL, что органика.** Отдельного `/direct/` нет. Первый экран этой страницы = топ-3.
- **«Все» = участники среза**, не «все прокаты рынка». Без брендовых запросов за год в срез не входят — правило методики скоринг-проекта; витрина состав не считает и не дополняет.
- **Сетка (§2).** После среза исследования канон `/kaliningrad/` = рейтинг-исследование. Топ-3 / топ-5 / топ-10 / полный список — разделы одной страницы; кнопки топ-3/5/10 = якоря на этой странице, не новые URL. `/zaprosy/` и `/otzyvy/` — доп. рейтинги с той же схемой и **теми же кнопками** топ-3/5/10 (одинаковые якоря разделов). До исследования `/kaliningrad/` — хаб без таблицы мест (описание и ссылки, без мест и баллов); URL не занимать другим рейтингом. Живые рейтинги: `/kaliningrad/zaprosy/` и `/kaliningrad/otzyvy/`. Четвёртого сводного нет. Отдельных URL топ-3/5/10 нет. Слаги в примерах — латиница (`kaliningrad`, `zaprosy`, `otzyvy`).
- **Хаб до research.** `/kaliningrad/` без таблицы мест принят. На хабе нет мест, баллов и кнопок топ-3/5/10 — только описание и ссылки на топ wordstat (`/kaliningrad/zaprosy/`) и отзовиков (`/kaliningrad/otzyvy/`). Кнопки топ-3/5/10 на хабе появятся только когда там будет рейтинг research; пока на хабе нет. Когда будет research — этот URL становится страницей исследования. В JSON ключа `tables.research` нет, пока свод не готов (не пустой массив).
- **Дизайн.** Принят визуальный микс: токены «Честного кубка» (цвет, pill-кнопки, форма блоков, значки) + структура витрины. Образец: [design-sample.md](design-sample.md). Не база «всё с кубка». Сравни — референс подачи comparison, не палитра: [sravni-dark.png](../media/references/sravni-dark.png). Баннер (принято): неширокая строка сверху (стандартный минимум РСЯ + туда же оповещения); пока слот пустой — **не рендерить**; точный размер — §11. Макеты и вёрстку не стартовать без JSON-пакета среза.
- **Строка среза.** В каждой таблице: `company_id` (стабильный kebab), `name`, `place` (место в этой таблице), `score` (число или `null`, если свод не готов). В новых пакетах не `id`/`rank`. Плюсы/минусы — опциональный `card` на той же строке (`card.pros[]`, `card.cons[]`); обычно `tables.research`; wordstat/reviews — только когда появятся формулировки; нет текста — поля `card` нет; пустую карточку и пустые массивы не отдаём.
- **Архив (§5).** В индексе — полная страница среза на дату. Архивные обрезки топ-3/5/10 не заводить.
- **Методика (§6).** Кратко на странице рейтинга + одна `/metodika/` на все регионы. Детали региона (дата / охват / версия) — на странице рейтинга. Формула — на методике, в регион не копировать.
- **Объём карточек.** Описания у топ-10, не у всего списка.
- **Подача страницы рейтинга.** Топ-3 с баллом → короткий блок доверия → карточки топ-10 из исследования → дальше полный список таблицей. Кнопки топ-3 / топ-5 / топ-10 — якоря разделов (не фильтры «по услугам»). На `/zaprosy/` и `/otzyvy/` кнопки те же. На хабе этих кнопок нет, пока нет research.
- **SEO-дополнение.** Только упаковка фактов среза (заголовок, лид, перефраз). Запрещено: новые плюсы, цифры, отзывы, места, шаблон «лучший прокат в {город}». Нет текста в срезе — нет карточки, только строка таблицы.
- **Отдельных URL компаний нет.** `/kaliningrad/{company}/` и аналоги не создавать. Карточки топ-10 живут только на странице рейтинга.
- **Статика из файла среза, не SPA.** Страница рейтинга — статический HTML из файла опубликованного среза. Новый срез → пересборка HTML + архив предыдущего. Не клиентское SPA. Живой скоринг на витрине нет. Стек (генератор, фреймворк) сейчас не выбирать.

Ранее принято и без изменений: один хост, регионы папками; URL региона/типа не открывать без среза; следующие регионы — строго по факту среза; издатель ООО «Рентпрог»; срез примерно раз в год; текущий виден до нового, старый — в архиве; канал органика; оговорки «не реклама» у таблицы без платных мест утверждены; места в таблице не продаются.

Нет данных: объёмы Wordstat / Keyword Planner; CPC; федеральный срез; состав, баллы, парки, отзывы, места. `wordstat` и `reviews` готовы в скоринге, `research` нет. Package JSON ещё не пришёл — ниже нет выдуманных цифр и мест.

Статика принята. Стек не выбирать. `wordstat` и `reviews` готовы, `research` нет. Хаб `/kaliningrad/` без таблицы мест принят. Микс принят (токены кубка + IA витрины). Баннер-слот пока пустой — не рендерить. Ждём package JSON; вёрстку без пакета не стартовать. Не внедрять. Открыто: точный размер баннера — §11.

## 2. Принятая сетка

Пути — схема URL, не прод-хост. Слаги в примерах — латиница (принято). Один набор слагов, не два дубля латиница+кириллица.

Старые три равноправных схемы (хаб трёх таблиц / ось типа с отдельными URL глубин / композитные топ-3/5/10) сняты с выбора. Не внедряются.

### Канон после среза исследования

Каждый тип рейтинга — свой канонический URL. Глубины топ-3 / топ-5 / топ-10 / полный список — **разделы одной страницы**, не отдельные документы. Кнопки топ-3 / топ-5 / топ-10 — якоря этих разделов, не новые URL и не фильтры «по услугам». На `/kaliningrad/zaprosy/` и `/kaliningrad/otzyvy/` кнопки **одинаковые** (та же схема якорей). На хабе `/kaliningrad/` кнопок нет, пока нет research.

| URL | Что это |
|---|---|
| `/kaliningrad/` | Канон региона = рейтинг-исследование. Подача: топ-3 с баллом → короткий блок доверия → карточки топ-10 из исследования → полный список таблицей. На странице: дата, охват, версия. Ссылка на `/metodika/` и на архив. |
| `/kaliningrad/zaprosy/` | Доп. рейтинг брендовых запросов. Та же схема одной страницы (глубины — разделы, не отдельные URL). |
| `/kaliningrad/otzyvy/` | Доп. рейтинг по отзовикам (Яндекс, Google, 2ГИС). Та же схема одной страницы. |
| `/metodika/` | Одна на весь сайт. Разделы трёх типов (запросы / отзовики / исследование). Формула здесь. |

Четвёртого сводного рейтинга нет: витрина не выводит «итоговый №1» средним трёх мест и не занимает под него URL.

Отдельных индексируемых URL `/top-3/`, `/top-5/`, `/top-10/`, `/vse/`, `/issledovanie/` нет. Это doorway: топ-3 ⊂ топ-5 ⊂ топ-10 ⊂ полный список одного среза.

На странице типа — одно именованное первое место этого рейтинга. Не «победитель региона» без имени рейтинга.

### До среза исследования

`/kaliningrad/` как рейтинг **не открывать**. URL не занимать другим рейтингом (не ставить туда запросы или отзовики «пока нет исследования»).

Факт: `wordstat` и `reviews` готовы, `research` нет. Живые рейтинги: `/kaliningrad/zaprosy/` и `/kaliningrad/otzyvy/`. Если среза типа нет — URL типа не открывать и не заполнять «для примера». `/metodika/` — на сайте, формула не зависит от открытия канона региона.

**Хаб (принято):** `/kaliningrad/` — хаб без таблицы мест: описание, издатель, даты срезов, ссылки на топ wordstat (`/kaliningrad/zaprosy/`), отзовиков (`/kaliningrad/otzyvy/`), metodika. Мест и баллов на хабе нет. Кнопок топ-3/5/10 на хабе нет; появятся только когда этот URL станет страницей research. Когда будет research — этот URL становится страницей исследования. В JSON ключа `tables.research` нет, пока свод не готов (не пустой массив). Не ставить wordstat/reviews таблицей на `/kaliningrad/` временно.

На корне в оглавлении — ссылки на хаб `/kaliningrad/` и на открытые типы.

Федеральный слой (`/rossiya/` и аналоги) — только после федерального среза. До этого в сетке его нет. Папка региона не появляется «чтобы заполнить оглавление».

### Директ

Объявление ведёт на канон того же типа, не на `/direct/`. Первый экран этой страницы = топ-3; ниже на той же странице — блок доверия, карточки топ-10 (на исследовании), полный список таблицей.

Отдельных платных посадочных топ-5/10 нет.

### Index

| URL | Органика | Директ |
|---|---|---|
| `/` оглавление | index | нет |
| `/metodika/` | index | нет |
| `/kaliningrad/` хаб до research; после свода — исследование | index как хаб сейчас (без таблицы мест); как рейтинг — только после среза исследования | после research: тот же URL, первый экран топ-3; до research хаб, не топ-3 |
| `/kaliningrad/zaprosy/` | index после среза этого типа | тот же URL, первый экран топ-3 |
| `/kaliningrad/otzyvy/` | index после среза этого типа | тот же URL, первый экран топ-3 |
| Отдельные `/top-3\|5\|10/`, `/vse/`, `/direct/` | не создавать | не создавать |
| Архив полной страницы среза | index, §5 | нет |

Три типа — не doorway друг к другу, **если** разные данные, разные методики, разные места.

Следующий тип рейтинга: сетка должна терпеть ещё один путь, но пустые папки и URL «на вырост» не создавать. Четвёртый сводный — не закладывать.

## 3. Почему не другие сетки (снято с выбора)

Не равноправные варианты, а отказ в пользу §2.

- **Хаб региона с тремя полными таблицами на `/kaliningrad/`.** Конфликтует с каноном «корень региона = исследование». До исследования занял бы URL чужим рейтингом. Это не то же, что принятый хаб **без** таблицы мест (§2).
- **Отдельные URL топ-3/5/10** (даже с `noindex`). Для органики не нужны; для Директа не нужны (тот же канон). Риск забыть `noindex` и получить doorway. Человекочитаемые якоря разделов на каноне достаточны.
- **Композит «на каждой глубине все три рейтинга».** Смешивает три №1 на обрезке; отдельные URL глубин — doorway.

## 4. Анти-паттерн doorway (не вариант)

Факты из справок и из [обзора практик](practices-overview.md). Не рецепт внедрения.

**Google.** Политика spam: страницы под близкие запросы, ведущие на «настоящий» контент; пачки почти одинаковых региональных/ключевых URL; scaled content — много страниц без самостоятельной пользы. Thin + doorway — основание ручной санкции. Программные страницы допустимы, только если у каждой своя польза, не подмена топонима и не обрезка того же списка.

**Яндекс.** Одинаковые страницы одного хоста склеиваются как дубли. Не плодить малоинформативные страницы отбора «по условию»; не создавать отдельную страницу под каждый запрос. SEO-тексты «под робота» — нарушение.

**Следствие:** топ-3 ⊂ топ-5 ⊂ топ-10 ⊂ полный список одной методики и даты. Четыре индексируемых URL с теми же строками разной длины — thin/doorway и, с высокой вероятностью, дубли у Яндекса. Уникальный абзац «почему топ-3» не делает документ другим, если главный контент — та же таблица.

Не индексировать одновременно:

- топ-3, топ-5, топ-10 и «все» одного среза;
- плюс те же обрезки ещё и по каждому типу;
- плюс шаблонные страницы регионов без среза;
- плюс отдельные посадочные Директа в индексе.

Это не сетка, а анти-паттерн. В канон не входит.

Как не получить doorway из глубин одного списка:

1. Индексировать **одну** каноническую страницу на тип рейтинга. Глубины — разделы/якоря на ней.
2. Не делать редирект «с топ-3 на полный список» как воронку с бесполезной промежуточной страницы.
3. Не генерировать пачку городов с шаблоном «топ автопрокатов {город}» до среза.
4. Архив по дате — не doorway к текущему (другой срез, другая дата). Текущий URL не дублирует архив той же даты.
5. Не канонилить Директ-страницу с другим содержанием на органику. Здесь Директ и органика — один URL, отдельной Директ-страницы нет.

Цифр спроса «топ-3 автопрокат Калининград» vs «рейтинг автопрокатов Калининград» нет.

## 5. Архив (принято)

В индексе — **архив полной страницы среза** (тот же тип, та же схема разделов, другая дата). Архивные обрезки топ-3/5/10 отдельными URL не заводить.

Пример схемы (не прод): `/kaliningrad/2025/` — архив исследования; `/kaliningrad/2025/zaprosy/`, `/kaliningrad/2025/otzyvy/` — архивы типов. Точный вид даты в пути ещё не выбираем.

Текущий срез остаётся на «живом» URL без даты. Два URL с одним и тем же срезом как два канона не держать.

## 6. Методика на витрине (принято)

Страница рейтинга = **подача среза**, не полная методика.

Подача (принято вместе с объёмом карточек): топ-3 с баллом → короткий блок доверия → карточки топ-10 из исследования → дальше полный список таблицей. Кнопки топ-3 / топ-5 / топ-10 — якоря на этой странице, не отдельные URL. На zaprosy и otzyvy кнопки те же. На хабе этих кнопок нет, пока нет research.

На странице рейтинга кратко: издатель, дата, охват, версия, ссылка «как считали». Формулы нет. Веса не переписывать. Если версия расчёта региональная — ссылка на раздел/версию общей методики. Редакционный балл не размечать как AggregateRating / звёзды отзывов.

Одна `/metodika/` на весь сайт, на все регионы. Разделы трёх типов (запросы / отзовики / исследование). Формула — здесь, в каждый регион не копировать. Это витринная публикация методики скоринг-проекта, не пересчёт весов здесь.

Если у типа нет среза — блока рейтинга нет, не заглушка с нулями.

Слаг `/metodika/` — латиница, как остальные примеры.

## 7. Именование мест и состав

На URL типа одно первое место. Имя рейтинга всегда раньше места: «Рейтинг брендовых запросов, 1-е место: {компания}», не «1-е место: {компания}» как победитель региона.

Не сливать три места в сводный №1. Сводного рейтинга нет.

Выдуманных плюсов/минусов и числа отзывов нет. Поля таблиц — только из опубликованного среза.

**Карточки (принято):** описания у топ-10, не у всего списка. Текст плюсов/минусов — из `card` на строке среза (обычно `tables.research`; wordstat/reviews — только если в пакете есть формулировки). Нет поля `card` — нет карточки, только строка таблицы. Карточка только на странице рейтинга, своего URL у компании нет.

**SEO-дополнение (принято):** только упаковка фактов среза (заголовок, лид, перефраз). Запрещено: новые плюсы, цифры, отзывы, места, шаблон «лучший прокат в {город}». Нет текста в срезе — нет карточки, только строка таблицы.

NN/g: компенсаторное сравнение устойчиво примерно при ≤5 альтернативах; полный список — скан, не сравнение. Дефолтная сортировка раздела = место этого рейтинга, не алфавит.

## 8. Баннер vs таблица

Утверждено: таблица без платных мест — не реклама. Баннер — другой контур.

**Принято:** неширокая строка сверху (стандартный минимум РСЯ + туда же оповещения). Пока слот пустой — **не рендерить** (нет высоты, нет CLS). Когда контент появится — включить. Крестик «скрыть» с кубка не брать. Креатив не внедрять. Точный размер строки открыт (§11). Макеты и вёрстку без JSON-пакета не стартовать.

- Строка **выше** таблиц и **вне** таблиц.
- Оговорки «не реклама / места не продаются / срез на дату» — **у таблицы**, не только в подвале.
- Пустую строку не заполнять заглушкой «здесь могла быть ваша реклама» на индексируемой странице.
- Если рекламодатель есть в таблице: в рейтинге место среза; в баннере — отдельно как реклама. Строку таблицы за оплату не подсвечивать.

## 9. Матрица ячеек

Логически: **регион × тип рейтинга × дата среза**. Глубина топа — не ось URL, а разделы страницы типа.

| Ось | Значения | Когда ячейка существует |
|---|---|---|
| Регион | папка (`kaliningrad` в примере) | Есть хотя бы один опубликованный тип. Сам `/kaliningrad/` как рейтинг — только со срезом исследования. До свода этот URL — хаб без таблицы мест (принято). |
| Тип | zaprosy; otzyvy; исследование на каноне региона | Только если этот тип есть в пакете среза на дату. |
| Глубина | топ-3; топ-5; топ-10; все | Разделы той же страницы. «Все» = участники среза. Карточки описания — у топ-10; дальше таблица. |
| Дата | текущий; архивные | Текущий на живом URL. Архив — отдельная полная страница среза на дату. |

Счётчик индексируемых URL ≠ числу логических глубин. Порядок величины на «сейчас» при двух открытых типах без исследования: хаб `/kaliningrad/` + 2 канона типов + корень + `/metodika/`. После исследования: 3 канона + корень + `/metodika/` (хаб становится страницей исследования). Плюс архив полных страниц по датам, без множителя ×4 за обрезки. Отдельных URL компаний нет (принято): в счётчик не входят.
