## Принято из скоринга

- Один JSON на одну дату: `docs/site-export/package-YYYY-MM-DD.json`
- Корень: `as_of` (YYYY-MM-DD), `methodology_version` (напр. `v3`), `region` (`kaliningrad`), `tables`
- Три таблицы в одном пакете, не три файла: `research`, `wordstat`, `reviews`. Канон: пока свод не готов — ключа `tables.research` нет (не пустой массив). **Факт выбранного пакета:** ключ есть; на страницы не публикуем.
- Стабильный `company_id` — kebab-латиница, не менять между годами
- Яндекс Драйв, Делимобиль и каршеринг Сити рент в пакет не входят (правило скоринга, витрина состав не дополняет)

Список `company_id` из скоринга (не рейтинг и не места): `amigo`, `city-rent`, `lite-rent`, `amber-car`, `a-prokat`, `trip-rent`, `spk`, `kenig-rent`, `pavlov`, `amber-rent`.

## Принято: схема строки

Владелец подтвердил. В каждой строке каждой таблицы одни и те же поля:

| Поле | Что |
|---|---|
| `company_id` | стабильный kebab; в новых пакетах не `id` |
| `name` | отображаемое имя |
| `place` | место в **этой** таблице; в новых пакетах не `rank` |
| `score` | число или `null`, если свод не готов |

Было `id` / `rank` — в новых пакетах только `company_id` / `place`.

Плюсы/минусы — опциональный объект `card` на той же строке:

- `card.pros[]`, `card.cons[]`
- Обычно `tables.research`
- `wordstat` / `reviews` — только когда появятся формулировки
- Нет текста — поля `card` нет вообще
- Пустую карточку и пустые массивы не отдаём
