# Контракт среза (входящий)

Дата сверки: 27 сентября 2026. Текст скоринг-проекта плюс схема строки, подтверждённая владельцем. Витрина баллы не считает и не выдумывает. Код, импорт и сборку страниц не делать.

## Принято из скоринга

- Один JSON на одну дату: `docs/site-export/package-YYYY-MM-DD.json`
- Корень: `as_of` (YYYY-MM-DD), `methodology_version` (напр. `v3`), `region` (`kaliningrad`), `tables`
- Три таблицы в одном пакете, не три файла: `research`, `wordstat`, `reviews`. Пока свод не готов — ключа `tables.research` нет (не пустой массив)
- Стабильный `company_id` — kebab-латиница, не менять между годами
- Яндекс Драйв, Делимобиль и каршеринг Сити рент в пакет не входят (правило скоринга, витрина состав не дополняет)

Список `company_id` из скоринга (не рейтинг и не места): `amigo`, `city-rent`, `lite-rent`, `amber-car`, `a-prokat`, `trip-rent`, `spk`, `kenig-rent`, `pavlov`, `amber-rent`.

## Принято: схема строки

Владелец подтвердил. В каждой строке каждой таблицы одни и те же поля:

| Поле | Что |
|---|---|
| `company_id` | стабильный kebab; в новых пакетах не `id` |
| `name` | отображаемое имя |
| `place` | место в **этой** таблице; в новых пакетах не `rank` |
| `score` | число или `null`, если свод не готов |

Было `id` / `rank` — в новых пакетах только `company_id` / `place`.

Плюсы/минусы — опциональный объект `card` на той же строке:

- `card.pros[]`, `card.cons[]`
- Обычно `tables.research`
- `wordstat` / `reviews` — только когда появятся формулировки
- Нет текста — поля `card` нет вообще
- Пустую карточку и пустые массивы не отдаём

## Статус таблиц (факт)

- `wordstat` и `reviews` готовы
- `research` нет
- В пакете ключа `tables.research` нет, пока свод не готов (не пустой массив)
- Мест и баллов в этом документе нет

## Соответствие сетке (принято)

Живые рейтинги — только со срезом этого типа. `/kaliningrad/` как рейтинг = исследование, когда свод готов. Wordstat/reviews на `/kaliningrad/` не ставить.

| Таблица в JSON | URL после публикации |
|---|---|
| `research` | `/kaliningrad/` — страница исследования, только когда свод готов |
| `wordstat` | `/kaliningrad/zaprosy/` |
| `reviews` | `/kaliningrad/otzyvy/` |

Сайт не пересчитывает, не склеивает три места в четвёртый рейтинг, не добавляет компании вне пакета.

## Хаб до research (принято)

Сетка «корень региона = исследование после свода» не отменяется.

- `/kaliningrad/` сейчас хаб **без таблицы мест**: описание, издатель, даты срезов, ссылки на топ wordstat (`/kaliningrad/zaprosy/`), отзовиков (`/kaliningrad/otzyvy/`), metodika
- На хабе нет мест и баллов
- Живые рейтинги: `/kaliningrad/zaprosy/`, `/kaliningrad/otzyvy/`
- Когда будет research — `/kaliningrad/` становится страницей исследования
- В JSON ключа `tables.research` нет, пока свод не готов (не пустой массив)
- Не ставить wordstat/reviews на `/kaliningrad/` временно
